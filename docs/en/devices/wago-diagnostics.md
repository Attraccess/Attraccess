# WAGO diagnostics

Open **WAGO → Diagnostics** on a controller row. The view polls every five seconds and provides an **Open configuration** action. The controller list continues to poll permanent heartbeat connectivity independently of commissioning.

Applied configuration is not proof of physical I/O readiness. Diagnostics consumes canonical source timestamps and optional `state.readiness.hardwareAvailable` when supplied. Reported availability is shown separately: `false` invalidates samples, while `true` does not prove physical I/O readiness, which remains **unknown**. Concrete legacy payloads without source timestamps have **missing** source freshness and are never current. Retained output state can be old. Recent faults remain visible for the retention window; their disappearance is not evidence of recovery.

## Reusable integration contracts

- `GET /api/wago/controllers/:id/diagnostics`: requires `resources.update`; missing controllers return 404. Registered through `WagoDiagnosticsController` in `backend/plugin.ts`, independently of the main controller.
- `GET /api/wago/resources/:id/diagnostics`: also requires `resources.update`. Returns controller associations and local reference warnings, not live connectivity. Looks up only this resource's WAGO flow nodes (1,000 plus a truncation sentinel), deduplicates controller IDs and inspects at most 20 controllers. Missing or failed controllers are individually marked unavailable; unrelated resources return no controllers. Truncation means additional warnings may exist.
- `ResourceDiagnostics` contributes only to `resource.overview`, avoiding query fan-out on resource lists. The host auth callback gates mounting with `resources.update`, including removal on permission loss. Association queries share a resource key and a 30-second cache freshness window, with no interval polling. Detailed `ControllerDiagnostics` mounts and polls only while the user opens a controller; closing unmounts it. Resource controls are never disabled by this contribution.
- `WagoDiagnostics` in `apps/plugins/wago/diagnostics-types.ts`: shared response contract for connectivity, draft/publication/application, runtime metadata, channels, faults, correlated acknowledgements, flow references and recent events.
- `useWagoDiagnostics(controllerId: number | null)` in `frontend/src/diagnostics.ts`: TanStack query result; null disables requests; key `['wago', 'diagnostics', controllerId]`; five-second polling; one retry. Hosts must provide the existing QueryClient context.
- `WagoStatus({ diagnostics: WagoDiagnostics })`: pure status view for embedding in commissioning/configuration screens; it does not fetch.
- `ControllerDiagnostics({ controllerId: number, onConfigure?: () => void })`: complete polling view with its own render-error boundary and request-error presentation.
- `WagoDiagnosticsBoundary`: isolates an embedded diagnostics subtree. Remount to retry after a render failure. This boundary does not cover failures loading the plugin bundle itself.
- `WagoService.diagnostics`: process-local store. `ingest(controllerId, suffix, Buffer)` accepts only the existing runtime topic suffixes; `command(controllerId, channelId, commandId)` registers outbound correlation; `read(controllerId)` returns a detached snapshot. The command-handler callback `onCommand` runs before MQTT publication, allowing even immediate acknowledgements and publish-only commands to be correlated.

## Bounds and protocol behavior

The store retains at most 256 controllers, 256 entries per channel collection (input, output, live measurement, cumulative measurement), 1,024 command correlations, and 50 events per controller for 15 minutes. Individual messages above 64 KiB are ignored. It stores no raw payloads, device error messages, pairing codes, enrollment secrets or MQTT credentials. Known fault codes are allowlisted; unknown codes become `runtime_fault`. The store creates no telemetry database writes or asynchronous message queue. Existing heartbeat persistence is checkpointed at 30 seconds using the receipt checkpoint, with immediate writes for metadata changes. Canonical heartbeat source time is persisted unchanged; legacy ordering has an independent process-local watermark between checkpoints.

Legacy producer shapes remain supported: `state` with `connected`, `revision`, `contentHash`, and boolean `outputs`; `measurements` with `channelId`, numeric `value`, and `unit`; `faults` with `channelId`, `code`, and `message`; and `acknowledgements` with `id` and `status`. Canonical consumer support additionally validates source timestamp, opaque boot stream ID (trim-nonempty, at most 128 characters, preserved verbatim) and category sequence, boolean inputs, and integer live/cumulative measurements with their transmitted units. Producers use UUIDs, but consumers do not require or lowercase them. Fresh heartbeats establish liveness independently of channel state. Boot tracking retains 16 retired IDs and six category counters and fails closed when exhausted. Samples still require fresh, connected state and matching configuration. Acknowledgements must match both the controller and a locally issued command. Legacy wall-clock heartbeat sequences do not support contiguous gap counting. In-memory rejection summaries match both revision and hash and expire after 15 minutes; persisted revision rejection records remain configuration history.

Flow references are derived from existing `plugin.wago.*` nodes and validated against the applied mapping and revision. Publication divergence is a separate warning. Only `plugin.wago.command` nodes on different resources generate control-conflict warnings. Missing channels and command revision mismatches are flagged. Each reference links to `/resources/:id/flows?node=<encoded node ID>`. The generic host selects and centers that node after measurement, without replacing unsaved edits; missing targets leave the flow unchanged. Results are capped at 1,000 references with explicit truncation. These warnings never block resource usage; required flow nodes determine gating.

## Explicit remaining scope

Event-node integration remains outside this slice. Canonical input and source-envelope consumption are implemented; producer integration and deployment verification remain separate work. Configuration and commissioning owners can embed the shared status view without editing their screens here. Producers must supply actual source timestamps for source freshness and actual hardware availability for that reported field. Full host plugin-load isolation remains the host's responsibility. Synthetic diagnostics tests and browser checks provide no physical hardware proof.

Permanent heartbeats use `parseHeartbeat` without requiring discovery pairing credentials, preserving source-time persistence, receipt checkpoints and legacy sequence guards. Discovery still requires pairing. A producer with only partial canonical metadata (for example timestamp/sequence without a stream ID) is rejected, not relabelled fresh. Deployment and hardware acceptance remain separate from software conformance tests.
