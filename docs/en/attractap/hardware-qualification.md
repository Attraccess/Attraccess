# Hardware qualification remains outstanding

No physical results are established by this software work. Before production apply or catalog ingestion, an independent reviewer must qualify representative units and sign a receipt bound to exact inventory and artifacts. Host TLS peers, test keys and simulated receipts are software evidence only. Never use synthetic receipts to authorize real apply or rollout.

Use the opened-enclosure, seven-day, EUR 1,000 target in [production security](production-security.md). Keep fault injection, side channels and invasive extraction explicitly unqualified. Upgrade hardware and obtain competent testing before claiming stronger resistance.

Record board and module identity, ESP32-S3 SoC/ECO, actual 16 MiB flash geometry, all eFuses, key purposes, free/protected blocks, security version, signing-key revocation capacity, download/debug restrictions and tool versions. Unknown or conflicting state is ineligible. Inventory before each irreversible step; stop if it differs from the reviewed manifest. Separate DS, Flash Encryption, NVS and firmware-signing purposes and per-device roots. Record fingerprints and digests, never secrets.

The reviewed nonsecret manifest must bind installation and reader, inventory, certificate/public-key fingerprints, bootloader/application/partition/identity/NVS-key image digests, tool identity, final protections and ordered operations. Default to dry-run. Before apply, reread actual state and validate independent qualification. After interruption, reconcile actual state against the manifest and operation journal; never assume a write succeeded or repeat an uncertain eFuse burn. Stop on conflicts and use protected recovery. Preserve the original inventory and evidence.

Use sacrificial units for irreversible tests. For every supported non-demo variant:

1. Verify image and bootloader fit, partition offsets/alignment and 16 MiB geometry. Provision distinct identities and purpose-specific roots. Interrupt each provisioning stage, restore power and demonstrate safe reconciliation or refusal.
2. Demonstrate real opaque DS signing and API interoperability over plain WS, including automatic time after repeated cold boots and API restarts. Copy encrypted flash to another MCU and show authentication fails. Measure entropy, latency and internal RAM headroom under maximum payloads, reconnects, queue pressure and allocation failure.
3. Try wrong server names/trust, expired/future/forged/revoked reader credentials, changed ciphertext, replay, stale time challenges, downgrade and cleartext fallback. Demonstrate failure without application dispatch. Exercise time-service outage and automatic recovery without an operator.
4. Inspect supported APIs, diagnostics, logs, UART/USB/JTAG, consoles, flash programmers and observed buses for identity/card secrets. Attempt extraction and flash copying. Record remaining RAM/session-key exposure and all unsuccessful or incomplete attempts.
5. Show that unsigned, modified and disallowed older images fail. Exercise signed OTA, anti-rollback, revocation capacity and approved locked-device recovery. Test interrupted updates, power loss, slot selection and retained nonsecret summary acknowledgment/rejection. Do not promise unrestricted USB recovery after locks.
6. With ATT-950 integrated later, exercise supported real cards and organization application slots. Verify enrollment, authentication, reset, supervision and confirmed on-card migration. Capture reader traffic and inspect device memory to show reusable card keys never arrive. Check wrong keys, copied UIDs and cross-reader/session/activation proofs. Preserve other organizations' slots.

The independent reviewer's RSA-3072-or-stronger key stays outside the provisioning/API account. Install its public key through a protected local path. A receipt includes version 1, model `existing-board-v1`, evidence class `hardware`, result `passed`, reviewer, qualification/expiry times, inventory/evidence digests and exact artifact SHA-256 digests. Sign canonical JSON under `ATTR-QUAL-V1\n` with RSA-PSS/SHA-256, MGF1-SHA-256 and 32-byte salt. Receipts expire within 366 days and deny on stale time, signature failure, mismatched images or inventory. Retain private captures under restricted access; publish only nonsecret measurements and limits.

After testing, document every measured result and remaining physical limit. Approval applies only to the exact qualified artifacts and inventory. It does not attest future firmware health, prevent use of stolen genuine hardware, or complete the deferred ATT-950 card integration.
