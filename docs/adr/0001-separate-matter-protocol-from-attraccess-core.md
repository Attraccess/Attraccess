# Separate Matter protocol operation from Attraccess core

Attraccess will act as a Matter controller only. A separately deployed Matter sidecar owns fabric credentials, commissioning protocol, attestation, sessions, subscriptions, reconnection, and low-level Matter storage, while Attraccess core owns the user-facing device registry, authorization, audit, resource flows, health interpretation, and UI. Initial BLE communication is relayed by the normal Attraccess frontend through Web Bluetooth on a customer's commissioning device; the browser handles GATT transport only, while protocol state and credentials remain in the sidecar. Thread remains optional infrastructure provided by a managed OTBR service and an external radio.

This boundary isolates protocol and credential failures from the core application, avoids giving the Attraccess server host Bluetooth privileges, and preserves Attraccess as the sole product and policy authority. Web Bluetooth commissioning is supported through compatible Chromium browsers; Bluefy is a tested, best-effort interim recommendation for iOS, with a first-party native Attraccess wrapper planned as separate follow-up work to proxy BLE and other native capabilities into the web UI. Attraccess will not depend on Home Assistant or another external Matter controller, and it will not expose Attraccess resources as Matter devices.
