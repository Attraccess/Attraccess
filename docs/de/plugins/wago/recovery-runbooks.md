# WAGO-Wiederherstellungs-Runbooks
<!-- llms-description: Sechs Runbooks für den Betrieb der WAGO-CC100-Integration, etwa bei Zugangsdaten-Kompromittierung, Broker-Ausfall und Controller-Austausch. -->

> [!NOTE]
> Nur verfügbar, wenn das Plugin **WAGO** installiert ist. Siehe [Plugins installieren](plugins/installing-plugins.md).

Sechs Szenarien für den Betrieb der WAGO-CC100-Integration. Sie verweisen auf die vorhandenen Verfahren, statt sie zu
wiederholen. Die letzte Spalte jedes Schritts nennt den automatisierten Test, der ihn prüft, oder lautet **nicht abgedeckt**. Ein Test
zeigt, dass sich die Software wie beschrieben verhält; er ist kein Nachweis für einen physischen Controller
([Sicherheitsgrenze](plugins/wago/safety-boundary.md)).

Die Tests liegen in `apps/plugins/wago/`, sofern nichts anderes angegeben ist. **Reliability** bezeichnet das gleichnamige Szenario des
[Reliability-Harness](plugins/wago/production-support.md#gemessene-grenzen), eine Simulatormessung.

**Die Inbetriebnahme ist destruktiv, und es gibt kein Backup der Workloads.** Die Installation der Laufzeit ersetzt, was auf dem
Controller liegt, und deaktiviert CODESYS dauerhaft. Weder ein Runbook hier noch irgendetwas in Attraccess erstellt eine Sicherungskopie früherer
Anwendungen oder Daten eines Controllers oder stellt sie wieder her. Speichern Sie vor der Inbetriebnahme selbst, was Sie benötigen.

## 1. Attraccess-Konfiguration und Laufzeit wiederherstellen

**Wann:** Der Attraccess-Server wurde aus einem Backup wiederhergestellt, umgezogen oder neu installiert, und die Controller sollen weiter funktionieren.

**Bevor Sie beginnen:** Die Wiederherstellung des Servers benötigt dasselbe **`AUTH_SESSION_SECRET`** wie das Original. Das Plugin verschlüsselt
seine gespeicherten Geheimnisse (verwalteter SSH-Zugang, Netzwerkänderungs-Payloads, Wiederherstellungskopien der Zugangsdaten-Rotation) mit einem Schlüssel,
der aus diesem Wert und der Plugin-ID abgeleitet wird (`apps/api/src/encryption/encryption.service.ts`,
`getPluginEncryptionKey`). Mit einem anderen Secret lassen sich diese Zeilen nicht entschlüsseln, und die betroffenen Controller müssen
neu registriert werden. Andere Server-Secrets sind zum Lesen der WAGO-Daten nicht nötig.

| Schritt                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Abgedeckt durch                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Stellen Sie die Attraccess-Datenbank und die Dateien wieder her und starten Sie den Server mit dem ursprünglichen `AUTH_SESSION_SECRET`.                                                                                                                                                                                                                                                                                                                                               | Round-Trip der Plugin-Secrets: `apps/api/src/encryption/encryption.service.spec.ts`. Wiederherstellung eines Backups: **nicht abgedeckt** |
| Lassen Sie den in Attraccess konfigurierten MQTT-Servereintrag unverändert. Die Controller verbinden sich mit ihren gespeicherten Zugangsdaten wieder mit demselben Broker.                                                                                                                                                                                                                                                                                                            | **Nicht abgedeckt**                                                                                                                       |
| Warten Sie auf Heartbeats. Der Server baut sein Bild aus Heartbeats und gehaltenem (retained) Zustand neu auf; die Controller behalten ihre akzeptierte Konfiguration, solange der Server ausfällt. Messwerte werden nicht gehalten: Ein unveränderter Messwert hat keinen Wert, bis der Controller ihn erneut veröffentlicht, innerhalb von etwa 30 s plus dem Abfrageintervall des Geräts ([Veröffentlichungstakt](plugins/wago/measurement-contract.md#veröffentlichungsrhythmus)). | `backend/diagnostics/store.spec.ts`; Reliability: `server-restart`                                                                        |
| Vergleichen Sie unter **Konfiguration** die angewendete Revision jedes Controllers mit der veröffentlichten. Veröffentlichen Sie nichts, solange sie nicht abweichen.                                                                                                                                                                                                                                                                                                                  | `backend/wago-configuration.service.spec.ts`                                                                                              |
| Ein Controller, dessen verwalteter Zugang sich nicht entschlüsseln lässt: Entfernen Sie ihn und nehmen Sie ihn erneut in Betrieb, siehe [Szenario 4](#_4-einen-controller-ersetzen).                                                                                                                                                                                                                                                                                                   | **Nicht abgedeckt**                                                                                                                       |
| Prüfen Sie nach der Wiederherstellung in der [Diagnose](plugins/wago/diagnostics.md) auf veraltete Controller und auf die Zähler verworfener Nachrichten.                                                                                                                                                                                                                                                                                                                              | `frontend/src/diagnostics/ControllerDiagnostics.spec.tsx`                                                                                 |

Vorhandenes Verfahren: [Wiederherstellung der Laufzeit](plugins/wago/cc100-runtime.md#wiederherstellung) (Container-Absturz, Neustart, ungültige Konfiguration).

## 2. Kompromittierte Zugangsdaten

**Wann:** Das Broker-Passwort, das Enrollment-Secret oder der SSH-Schlüssel eines Controllers ist möglicherweise offengelegt worden.

| Schritt                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Abgedeckt durch                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rotieren Sie die Broker-Zugangsdaten des Controllers. Dafür gibt es in der Oberfläche keine Schaltfläche: Ein Administrator mit `system.settings.manage` ruft `POST /api/wago/controllers/<id>/credentials/rotate` auf (`<id>` ist die numerische Attraccess-ID des Controllers) und übergibt den Body `{"confirm": true}` als ausdrückliche Zustimmung. Die Laufzeit muss `credential-rotation-v1` melden. Details: [Zugangsdaten-Rotation](plugins/wago/credential-rotation.md). Solange die ACL des Controllers nicht eingeschränkt ist (ATT-1057), können die offengelegten Zugangsdaten diesen Controller steuern und seine Konfiguration ersetzen ([Bedrohungsmodell](plugins/wago/threat-model.md#_2-mqtt-autorisierung)); rotieren Sie daher zuerst. | `backend/credentials/service.spec.ts`; `acceptance/credential-rotation-mqtt.spec.ts`; `cc100-runtime/src/runtime/identity/rotation.spec.ts`; Reliability: `credential-rotation` |
| Läuft die Rotation in ein Timeout, wiederholen Sie sie mit `{"confirm": true, "retry": true}`: Die gespeicherten Zugangsdaten und das Token werden wiederverwendet, der Broker wird nicht erneut rotiert.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | `backend/credentials/service.spec.ts`                                                                                                                                           |
| Meldet die Laufzeit die Fähigkeit nicht, aktualisieren Sie sie zuerst (Szenario 5) oder entfernen Sie den Controller und registrieren Sie ihn neu.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | `backend/credentials/service.spec.ts` (ältere Laufzeiten scheitern bei der Zulassung)                                                                                           |
| Widerrufen Sie ein kompromittiertes, nicht beanspruchtes Enrollment, indem Sie die Sitzung abbrechen. Die Enrollment-Zugangsdaten laufen außerdem nach 15 Minuten ab.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | **Nicht abgedeckt**                                                                                                                                                             |
| Ersetzen Sie bei einem offengelegten SSH-Schlüssel den Verwaltungsschlüssel über die Wiederherstellungsoptionen des Controllers. Siehe [Wiederherstellung bei der Inbetriebnahme](plugins/wago/cc100-commissioning.md#wiederherstellung).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | **Nicht abgedeckt**                                                                                                                                                             |
| Rotieren Sie die Administrator-Zugangsdaten des Brokers selbst. Attraccess kann das nicht.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | **Nicht abgedeckt**                                                                                                                                                             |
| Prüfen Sie den Audit-Verlauf: [Audit-Integration](plugins/wago/audit-integration.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `backend/audit/audit.spec.ts`                                                                                                                                                   |

Das Bedrohungsmodell listet auf, was ein Angreifer mit den Zugangsdaten eines Controllers tun kann und was nicht:
[Bedrohungsmodell](plugins/wago/threat-model.md#_2-mqtt-autorisierung).

## 3. Broker-Ausfall

**Wann:** Der MQTT-Broker ist ausgefallen, nicht erreichbar oder wurde ersetzt.

| Schritt | Abgedeckt durch |
| ------- | --------------- |
| Rechnen Sie damit, dass Befehle wie bei einem Offline-Controller in ein Timeout laufen, und dass jeder Ausgang seiner Trennungsrichtlinie folgt (`hold`, `immediate`, `watchdog`). Das sind Betriebskontrollen, keine Sicherheitskontrollen. | `cc100-runtime/src/runtime/commands/disconnect.spec.ts`; Reliability: `broker-outage` (30 s) |
| Stellen Sie den Broker mit den **gleichen Konten und Topic-Richtlinien** wieder her. Controller und Server verbinden sich von selbst neu.                                                                                                    | Reliability: `broker-outage`, `connection-loss`                                              |
| Prüfen Sie die physischen Ausgänge, bevor Sie den normalen Betrieb wieder aufnehmen.                                                                                                                                                         | **Nicht abgedeckt** (eine Person muss prüfen)                                                |
| Prüfen Sie den gehaltenen (retained) Zustand und den letzten Heartbeat in der [Diagnose](plugins/wago/diagnostics.md).                                                                                                                       | `frontend/src/diagnostics/ControllerDiagnostics.spec.tsx`                                    |
| Wurde der Broker ersetzt und seine Konten sind weg, können sich die Controller nicht authentifizieren. Registrieren Sie jeden neu (Szenario 4).                                                                                              | **Nicht abgedeckt**                                                                          |
| Setzen Sie die maximale Nachrichtengröße des Brokers auf 2 MiB. Siehe [Produktivbetrieb und Kompatibilität](plugins/wago/production-support.md#broker-einstellungen).                                                                        | Reliability: `oversized-messages`                                                            |

Vorhandenes Verfahren: [Broker-Verlust](plugins/wago/cc100-runtime.md#brokerverlust).

## 4. Einen Controller ersetzen

**Wann:** Ein CC100 ist ausgefallen oder wird gegen ein anderes Gerät getauscht.

| Schritt                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Abgedeckt durch                                                                                                    |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Notieren Sie Namen und Kanalzuordnung des alten Controllers. Bewahren Sie seinen Konfigurations-Revisionsverlauf auf; Revisionen bleiben in Attraccess erhalten.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | `backend/wago-configuration.service.spec.ts`                                                                       |
| Sichern Sie angeschlossene Anlagen ab und entfernen Sie dann den alten Controller aus Attraccess. Das Entfernen widerruft seinen MQTT-Zugang. Es deinstalliert nichts auf dem alten Gerät.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | `backend/wago-claim-ownership.spec.ts` (Widerruf beim Entfernen)                                                   |
| Nehmen Sie den neuen CC100 mit dem geführten Ablauf in Betrieb. Das ist **destruktiv**: Es ersetzt die Software und deaktiviert CODESYS, und Attraccess erstellt keine Sicherungskopie von dem, was auf dem Gerät ist.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `acceptance/commissioning/commissioning.spec.ts`; Anleitung: [Inbetriebnahme](plugins/wago/cc100-commissioning.md) |
| Kopieren Sie die bisherige Kanalkonfiguration auf den neuen Controller und veröffentlichen Sie sie als neue Revision. Prüfen Sie vorher die Auswirkungen auf Flows.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | `backend/wago-configuration.service.spec.ts`                                                                       |
| Lehnt der neue Controller die Konfiguration mit `configuration_limit_exceeded` ab, verkleinern Sie sie und veröffentlichen Sie eine neue Revision. Ein neuer oder zurückgesetzter Controller hat keine gespeicherte akzeptierte Konfiguration und prüft deshalb bei jeder empfangenen Revision die Konfigurationsgrenzen, auch bei einer gehaltenen (retained) Revision, die vor Einführung dieser Grenzen veröffentlicht wurde. Ein Controller, der diese Revision bereits ausführt, überspringt die Prüfung nur, weil Revision und Hash der gespeicherten entsprechen. Beispiel: Zwei eingebaute 879-3020-Zähler mit allen 131 aktivierten Messwerten überschreiten die Grenze von 256 aktivierten Kanälen; klicken Sie in den Einstellungen jedes Zählers auf **Nur empfohlene Messwerte** und veröffentlichen Sie erneut. | `cc100-runtime/src/runtime/limits.spec.ts`                                                                         |
| Aktualisieren Sie Flows, die auf den alten Controller verweisen.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | `backend/flow/service.spec.ts`                                                                                     |
| Prüfen Sie die physischen Ausgänge, bevor Sie den Controller wieder in Betrieb nehmen. Der physische Einsatz ist bis ATT-984 unqualifiziert.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | **Nicht abgedeckt**                                                                                                |

## 5. Laufzeit-Upgrade und Rollback

**Wann:** Eine neue Laufzeitversion erscheint oder ein Controller meldet eine Software-Abweichung.

**Nach einem Server-Update, das die Laufzeit `0.3.0` mitbringt:** Verwaltete CC100 aktualisieren sich einmal automatisch und halten ihre Ausgänge aus, bis
der Server das laufende Image bestätigt (`runtime-update-gate-v1`). **Nicht verwaltete CC100** (von Hand installiert oder vor den
verwalteten Updates registriert) werden nicht aktualisiert; sie bleiben im Failsafe mit ausgeschalteten Ausgängen und lehnen Befehle ab, bis jemand sie
von Hand aktualisiert.

| Schritt                                                                                                                                                                                                                                                                                                                                                                                                                                              | Abgedeckt durch                                                                                          |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Verwalteter Controller: Lassen Sie den Abgleich laufen oder beobachten Sie den Status **Software-Update**. Höchstens zwei Updates laufen gleichzeitig.                                                                                                                                                                                                                                                                                               | `backend/runtime/update/coordinator.spec.ts`; `backend/runtime/managed/service.spec.ts`                  |
| Ein fehlgeschlagenes Update wird auf den aufbewahrten Vorgänger zurückgesetzt. Prüfen Sie das Seitenpanel **Details** auf den klassifizierten Grund.                                                                                                                                                                                                                                                                                                 | `backend/runtime/update/coordinator.spec.ts`; `backend/runtime/lifecycle-interruption.spec.ts`           |
| Die Ausgänge bleiben aus und Befehle werden abgelehnt, bis der Server das Image bestätigt; fehlgeschlagene Herunterfahrvorgänge halten die Bereitschaft auf „false“ und werden wiederholt.                                                                                                                                                                                                                                                           | `cc100-runtime/src/runtime/startup.spec.ts`                                                              |
| Nicht verwalteter Controller: Entfernen Sie ihn und nehmen Sie ihn mit dem geführten Ablauf erneut in Betrieb (er wird nicht automatisch migriert), oder folgen Sie den manuellen Image-Schritten unter [Laufzeit: ein Image zurücksetzen](plugins/wago/cc100-runtime.md#image-oder-konfiguration-zurücksetzen) mit dem neuen Digest. Behalten Sie den bisherigen Digest und das State-Volume, bis das neue Image akzeptiert ist.                    | **Nicht abgedeckt**                                                                                      |
| Setzen Sie eine Konfiguration zurück, indem Sie den vorherigen Snapshot als neue Revision veröffentlichen. Bearbeiten Sie niemals `state.json`.                                                                                                                                                                                                                                                                                                      | `backend/wago-configuration.service.spec.ts`                                                             |
| Gemischte Versionen: Eine ältere Laufzeit arbeitet weiter mit einem neueren Server und umgekehrt; Verwerfungszähler erscheinen nur für Laufzeiten, die `bounded-messages-v1` melden.                                                                                                                                                                                                                                                                 | `backend/diagnostics/store.spec.ts`                                                                      |
| Aktualisieren Sie Laufzeiten älter als `0.3.0`, bevor Sie sich auf Ablehnungsberichte verlassen. Sie veröffentlichen Ablehnungsberichte beliebiger Größe, und der Server ignoriert jede Controller-Nachricht über 64 KiB oder mit mehr als 8 Verschachtelungsebenen. Eine sehr große Ablehnung einer solchen Laufzeit führt dazu, dass die Revision als veröffentlicht ohne Ablehnung angezeigt wird.                                                | `backend/protocol/payload-limits.spec.ts` (Serverseite); Verhalten alter Laufzeiten: **nicht abgedeckt** |
| Führen Sie kein Downgrade von Server oder Laufzeit auf eine Version ohne Unterstützung für deaktivierte Kanäle (`enabled`) durch, solange ein Kanal deaktiviert ist: Diese lehnt die gespeicherte Konfiguration ab („persisted configuration is invalid“). Veröffentlichen Sie vor einem Downgrade eine Revision, in der alle Kanäle aktiviert sind, zum Beispiel indem Sie auf eine Revision von vor der Deaktivierung von Messwerten zurücksetzen. | **Nicht abgedeckt**; nicht auf Hardware getestet                                                         |

## 6. Disaster Recovery

**Wann:** Server, Broker und möglicherweise Controller gehen gemeinsam verloren.

| Schritt | Abgedeckt durch |
| ------- | --------------- |
| Bauen Sie in dieser Reihenfolge neu auf: Broker, Attraccess-Server (Datenbank und ursprüngliches `AUTH_SESSION_SECRET` wiederherstellen), dann Controller. | **Nicht abgedeckt** |
| Legen Sie die Broker-Konten und Topic-Richtlinien neu an. Ohne sie können sich Controller nicht authentifizieren; legen Sie sie über die Zugangsdaten-Rotation neu an, wenn der Controller erreichbar ist, andernfalls registrieren Sie ihn neu. | `backend/credentials/service.spec.ts` (Rotation); Neuregistrierung: **nicht abgedeckt** |
| Controller, die noch laufen, behalten ihre akzeptierte Konfiguration und wenden ihre Trennungsrichtlinie an, solange der Broker fehlt. | `cc100-runtime/src/runtime/commands/disconnect.spec.ts` |
| Ersetzen Sie einen verlorenen Controller (Szenario 4). Seine bisherige Workload lässt sich nicht wiederherstellen. | **Nicht abgedeckt**, gewollt |
| Führen Sie vor der Wiederaufnahme des Betriebs die Prüfungen aus dem [Leitfaden zu Abnahmenachweisen](plugins/wago/acceptance-evidence.md) durch. | **Nicht abgedeckt** (Hardware) |

## Was die Laborübungen abdecken

Die obigen Szenarien werden in den Laborübungen an einem echten CC100 durchgespielt. Sie sind noch nicht durchgeführt worden. Die Ergebnisse werden auf der Seite
[Produktivbetrieb und Kompatibilität](plugins/wago/production-support.md#laborübungen) festgehalten.
